# 🧰 Frontend Project Guardian

这是我创建出来的一个前端和客户端项目开发 Skill。

我做它的目的，不只是让 AI 帮我写代码，而是让我在做前端项目时，有一套更稳、更清楚、更容易交接的工作方式：
先分析需求和现状，再给方案，等我确认后再实施，最后再做验证和收尾同步。

---

## 我为什么要做这个 Skill

我在前端开发里最在意的，不是“能不能很快写出来”，而是“能不能稳定交付、能不能接得住后续修改、能不能让别人一看就明白”。

我做这个 Skill，就是为了尽量避免这些常见问题：

- 需求还没看清就直接开改
- 没先判断项目现状，就乱套默认技术栈
- 页面只做到“能用”，没顾到空态、错误态、加载态和响应式
- 改完代码就结束，没有配套的验证思路
- 到了收尾阶段，README、文档、记忆和代码已经不一致
- 下一次接手的人，看文档和看代码像在看两个项目

所以我给自己做了这个 Skill。
它会提醒 AI 先分析，再提方案，等我确认后再动手；
到项目接近里程碑或收尾阶段时，它还会主动提醒做文档同步，避免知识越积越乱。

---

## 这个 Skill 适合什么场景

这个 Skill 适合我做绝大多数前端和客户端开发任务，尤其是这些：

- Web 前端开发
- 微信小程序开发
- Taro 项目
- uni-app 项目
- App / 混合 App 项目
- 页面和模块开发
- Bug 修复
- 重构和工程整理
- UI 优化
- Code Review
- 项目收尾和文档同步
- 新项目初始化
- 旧项目接手和二次开发

如果我给 AI 的不是一个很简单的改字任务，而是一个完整的开发任务，比如“做页面”“修 bug”“重构模块”“补文档”“review 改动”，这个 Skill 就应该生效。

## 我希望它约束 AI 做什么

### 1. 先看项目现状，不盲目套默认栈

我不希望 AI 一上来就默认这是 Vue、Vite 或 Pinia。

它应该先看这些东西：

- `package.json`
- `package.json` 里的 scripts 和 dependencies
- `README.md`
- 平台或构建配置文件，比如 `vite.config.*`、`tsconfig.*`、`project.config.json`、`app.json`、`pages.json`、`manifest.json`
- 现有目录结构和已有组件写法

如果项目已经明确表达了自己的技术路线，AI 应该优先跟随项目本身，而不是强行换成默认模板。

### 2. 先出方案，再等我确认

我不希望 AI 默默开始改代码。

我希望它先：

1. 分析任务
2. 给出方案
3. 说明会改哪些文件、哪些模块、可能有什么风险
4. 等我确认后再实施

如果我中途修订需求，它应该把这次修订当成新的检查点，重新判断影响范围。

### 3. 大改动前先审批

只要涉及下面这些内容，就应该先停下来让我确认：

- 新建项目结构
- 改配置
- 装依赖
- 引入新 UI 库
- 大范围重构
- 影响多个文件或多个模块的修改
- 重要验证命令

### 4. 做 UI 时不只看“能不能跑”

我希望 AI 在做 UI 时，别只停在“页面能打开”。

它还要一起考虑：

- 交互反馈
- 加载状态
- 空状态
- 错误状态
- 禁用状态
- 响应式
- 平台差异

我希望最终交出来的，不只是代码，而是像能直接交付的产品界面。

### 5. 收尾阶段主动做知识同步

如果当前任务已经到了里程碑、收尾、整理、同步文档这一类阶段，我希望 AI 自动切到“知识对齐”模式：

- 检查 `README.md`、`CLAUDE.md`、`AGENTS.md`、`docs/` 是否过期
- 删除过时信息
- 修正文档和代码不一致的地方
- 让下一次接手的人一眼能看懂当前状态

## 这个 Skill 包含哪些方面

| 方面            | 说明                                                |
| --------------- | --------------------------------------------------- |
| 前端/客户端开发 | Web、小程序、App、混合项目都能用                    |
| 现状识别        | 先看 `package.json`、脚本、依赖和配置文件           |
| 方案优先        | 先给方案，再开始实施                                |
| 审批控制        | 大改、装依赖、改配置前先确认                        |
| 工程质量        | 可读、可维护、边界清晰                              |
| UI 体验         | `loading` / `empty` / `error` / `disabled` / 响应式 |
| Review 模式     | 优先检查 bug、回归、边界、测试缺口                  |
| 收尾同步        | milestone 时同步文档和项目说明                      |
| 交接意识        | 让下一次接手的人能直接继续                          |

## 使用方式

使用时不需要记复杂命令。

当你开始一个前端任务时，它会自动按这个顺序工作：

1. 先分析需求和项目现状
2. 再给出实施方案
3. 等我确认后再开始改动
4. 完成后给出验证建议
5. 如果是收尾阶段，再同步文档和知识

你也可以直接这样描述需求：

- “帮我做一个微信小程序页面”
- “这个 Vue 页面有 bug，先帮我看原因”
- “我要重构这个模块，先出个方案”
- “帮我 review 一下这次改动”
- “这个阶段做完了，帮我同步一下文档”
- “我要新起一个前端项目，先帮我定流程”
- “这个项目是 Taro / uni-app 的，按现有栈帮我整理一下”

## 安装方式

### 方式 1：给 Agent 直接安装目录链接（推荐）

在支持 Skill 的 Agent 里，直接说：

> 帮我安装这个 skill: `https://github.com/zyusong35-hash/frontend-project-guardian/tree/main/frontend-project-guardian`

### 方式 2：打开仓库后手动进入目录

如果先打开的是整个仓库主页，也可以这样做：

1. 先进入仓库首页
2. 点击 `frontend-project-guardian` 这个目录
3. 再打开里面的 `SKILL.md`
4. 把这个目录地址复制给支持 Skill 的 Agent
